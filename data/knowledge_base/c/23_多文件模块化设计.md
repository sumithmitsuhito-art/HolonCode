# 模块 23：多文件模块化设计

## 一、为什么要分模块

- 代码清晰：每个文件只做一件事
- 可并行：多人协作不同文件
- 可复用：通用模块放到其他项目
- 编译快：改一个文件只重编译它

## 二、模块化原则

### 1. 高内聚、低耦合
- 一个文件内部逻辑尽量紧密（高内聚）
- 文件之间互相依赖尽量少（低耦合）

### 2. 头文件只有"对外接口"
```c
// ==== stack.h：对外接口 ====
#ifndef STACK_H
#define STACK_H
#include <stdbool.h>

typedef struct Stack Stack;     // 前向声明（不暴露内部结构，信息隐藏）

Stack *stack_create(int capacity);
void   stack_free(Stack **pps);
bool   stack_push(Stack *s, int value);
bool   stack_pop (Stack *s, int *out_val);
int    stack_size(const Stack *s);

#endif
```

```c
// ==== stack.c：具体实现 ====
#include "stack.h"
#include <stdlib.h>

struct Stack {                // 内部结构只在 .c 可见（封装！）
    int *data;
    int   size;
    int   cap;
};

Stack *stack_create(int cap) {
    Stack *s = malloc(sizeof(Stack));
    if (!s) return NULL;
    s->data = malloc(cap * sizeof(int));
    if (!s->data) { free(s); return NULL; }
    s->size = 0; s->cap = cap;
    return s;
}

// ... 其他函数实现 ...
```

## 三、static 做"私有"

```c
// stack.c 内部使用的辅助函数
static void resize(Stack *s) {    // 加了 static，别的文件看不见
    /* ... */
}
```

## 四、循环引用

```c
// 坏：a.h include b.h，b.h include a.h → 死循环
// 好：头文件尽量不 include 其他头，用"前向声明"
// 真的需要对方具体类型时，再把 include 写在 .c 里
```
