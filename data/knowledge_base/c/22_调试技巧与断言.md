# 模块 22：调试技巧与 assert

## 一、printf 调试法（最简单、80% 场景够）

```c
// 用宏统一开关
#ifdef DEBUG
    #define DBG(fmt, ...) fprintf(stderr, "[%s:%d] " fmt "\n", \
                                       __FILE__, __LINE__, ##__VA_ARGS__)
#else
    #define DBG(fmt, ...) ((void)0)
#endif

DBG("x = %d, y = %d", x, y);   // 编译加 -DDEBUG 就打印
```

特殊宏：`__FILE__`（文件名）、`__LINE__`（行号）、`__func__`（函数名）

## 二、assert 断言（`<assert.h>`）

断言 = "我认为这里一定为真，否则程序有 bug"。

```c
#include <assert.h>
void pop(Stack *s) {
    assert(s != NULL);        // s 不能为空！
    assert(s->top > 0);       // 不能空栈 pop
    s->top--;
}
```

- `NDEBUG` 宏定义后，assert 被完全禁用（不生成任何代码）
- 发布版通常加 `-DNDEBUG` 关掉 assert
- 千万不要在 assert 里写有副作用的代码：`assert(++x > 0)` → 关掉 NDEBUG 后 x 永远不增！

## 三、gdb 基础（命令行调试器）

```bash
gcc -g buggy.c -o buggy    # -g 加调试信息
gdb ./buggy
```

常用命令：

| 命令 | 缩写 | 作用 |
|------|------|------|
| `run` | `r` | 启动程序 |
| `break 行号/函数` | `b` | 下断点 |
| `next` | `n` | 单步，不进函数 |
| `step` | `s` | 单步，进入函数 |
| `print 变量` | `p` | 看变量值 |
| `info locals` | `i locals` | 所有局部变量 |
| `continue` | `c` | 继续到下一个断点 |
| `backtrace` | `bt` | 调用栈（看崩在哪） |
| `quit` | `q` | 退出 |

## 四、段错误排查步骤

1. 用 gcc **-g -O0** 编译
2. `ulimit -c unlimited`（允许生成 core dump）
3. 运行生成 core 文件
4. `gdb ./a.out core` → `bt` 直接看崩溃栈
5. 如果指针问题：在可疑处加 `assert(p != NULL)`，再用 valgrind（Linux）检查越界
