# 模块 25：常见陷阱与最佳实践

## 一、Top 10 经典陷阱

### 1. `=` vs `==` 混淆
```c
if (a = 0) { }     // ❌ 赋值，永远为假。gcc -Wall 会警告
```

### 2. scanf 忘记 `&`
```c
int n;
scanf("%d", n);    // ❌ 崩溃。必须 &n
```

### 3. gets / 无界 scanf
```c
char buf[10];
gets(buf);                // ❌ C11 已删除
scanf("%s", buf);         // ❌ 可能溢出
fgets(buf, sizeof(buf), stdin);  // ✅
scanf("%9s", buf);        // ✅ 指定宽度
```

### 4. `printf` 格式化符不匹配
```c
printf("%d", 3.14);   // ❌ 格式和类型不匹配
printf("%ld", (long)x);   // 始终注意 cast
```

### 5. 悬空 else
```c
if (a)
if (b) x++;
else y++;   // else 属于第二个 if，不是第一个
```

### 6. 数组越界
```c
int a[10]; for (int i=0; i<=10; i++) a[i] = 0;   // i<=10 越界
```

### 7. 字符串常量不能写
```c
char *p = "abc";
p[0] = 'A';     // ❌ 段错误（字符串常量在只读段）
```

### 8. switch 忘 break → 穿透
```c
case 1: do_something();   // 忘 break，继续执行 case 2...
case 2: ...
```

### 9. 不检查 malloc / fopen 返回值
```c
int *p = malloc(N);   // ❌ 不检查失败
p[i] = x;             // 内存不够时直接崩
```

### 10. 忘记 free 或 double free

## 二、最佳实践清单

✅ **必须做**
- 编译开 `-Wall -Wextra`
- 数组下标严格检查边界
- 所有动态分配检查返回值
- `scanf` 永远指定 `%Ns` 限制长度
- 头文件有保护 `#ifndef / #define / #endif`
- 传结构体用指针 + `const`（除非很小）

⚠️ **不要做**
- 不要写 `void main()`（标准写 `int main(void)` 或 `int main(int argc, char **argv)`）
- 不要用 `gets()`、`fflush(stdin)`（未定义行为）
- 不要在头文件里定义变量/函数（会 multi-definition）
- 不要在 assert 中写有副作用的代码

## 三、编码规范（简单版）

1. **命名**：
   - 变量、函数：`snake_case` （`int student_count;`）
   - 宏常量：`UPPER_CASE`（`#define MAX_LEN 100`）
   - 类型名（typedef struct）：`PascalCase`（`typedef struct { ... } Student;`）
2. **缩进**：统一用 4 空格（不混用 Tab）
3. **大括号**：K&R 风格或 Allman 风格都行，**项目内统一**
4. **一行一个声明**
5. **指针 `*` 挨着变量名**：`char *p, *q;` （`char* p,q;` 坑：q 是 char）
