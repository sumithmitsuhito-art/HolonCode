## 新手操作指南

> 如果你是第一次使用本软件，完全不知道从哪里开始，请跟着下面的步骤一步步来。每一步都非常详细，照着做就行。

### 第一步：认识界面

软件窗口分为三个区域：

| 区域 | 位置 | 作用 |
|------|------|------|
| 左侧边栏 | 最左边 | 会话列表 + 底部快捷按钮（C语言知识闯关、C语言答疑） |
| 中间聊天区 | 正中间 | 和 AI 对话的地方，消息在这里显示 |
| 右侧文件面板 | 最右边 | 管理 workspace 文件夹里的文件 |

**现在请看一眼屏幕右侧的文件面板**，标题显示 "workspace"，下面有一个树形文件列表。你写的所有 C 代码都会保存在这里。

### 第二步：在文件面板中创建 C 文件

有两种方法创建你的第一个 .c 文件：

**方法一（推荐）：直接告诉 AI**
在底部输入框输入：
```
请帮我在 workspace 里创建一个 hello.c 文件
```
AI 会自动帮你创建，然后你可以双击打开。

**方法二：手动创建**
1. 点击右侧文件面板底部的 **"在资源管理器中打开"** 按钮
2. 系统会弹出一个文件资源管理器窗口，这就是 workspace 文件夹
3. 在空白处右键 → 新建 → 文本文档
4. 把文件名改成 `hello.c`（注意：`.txt` 后缀要改成 `.c`）
5. 如果系统提示"改变文件扩展名可能导致文件不可用"，点 **"是"**
6. 回到软件，点击文件面板的 **"刷新"** 按钮，就能看到刚创建的 `hello.c` 了

### 第三步：打开文件并写代码

1. 在右侧文件面板中 **双击** `hello.c`
2. 会弹出一个 **文件预览窗口**，包含：
   - 顶部：文件路径
   - 中间：代码编辑区（有行号、语法高亮）
   - 底部：保存 / 取消 按钮
3. 在编辑区输入你的 C 代码，例如：
```c
#include <stdio.h>

int main() {
    printf("Hello, World!\n");
    return 0;
}
```
4. 写好代码后点击 **"保存"** 按钮，窗口自动关闭

### 第四步：让 AI 检查你的代码

回到中间的聊天输入框，输入：
```
我写好了 hello.c，帮我看看
```
或者直接说：
```
检查一下我的代码
```
AI 会读取你的文件、审查代码、给出评分和建议。

### 第五步：修改代码后重新提交

1. 再次双击文件面板中的 `hello.c` 打开预览窗口
2. 根据 AI 的建议修改代码
3. 点击 **"保存"**
4. 在聊天框告诉 AI：`我改好了，再看看`

### 第六步：进入下一关

### 改错关卡 01 — 基础语法排错
**知识点覆盖：** 关卡 01-02（程序结构、变量类型、printf/scanf）

**AI 操作：** 用 write_file 将以下代码写入 workspace 的 `debug01.c`，然后告诉用户：
"我写了一段代码，本意是让用户输入两个整数并输出它们的和，但里面有 3 个 bug。你能帮我找出来并修复吗？"

**预设错误代码：**
```c
#include <stdio.h>

int main() {
    int a, b;
    printf("请输入两个整数：")
    scanf("%d %d", a, b);
    int sum = a + b;
    printf("和 = %d\n", sum)
    return 0;
}
```

**预设 bug 清单（3 个）：**
1. 第 5 行 `printf("请输入两个整数：")` 末尾缺少分号
2. 第 6 行 `scanf("%d %d", a, b)` 缺少 `&`，应为 `&a, &b`
3. 第 8 行 `printf("和 = %d\n", sum)` 末尾缺少分号

**引导要点：**
- 用户如果只找到 1-2 个 bug，提示"再看看，还有哦"，但不要直接说哪里
- 用户如果完全找不出来，提示"试试编译一下，编译器会告诉你哪里有问题"
- 用户修复后，让他解释为什么 `scanf` 要加 `&`
- 最后总结：C 语言每个语句必须以分号结尾，`scanf` 需要变量的地址才能写入

### 选择题关卡 01 — 基础概念选择
**知识点覆盖：** 关卡 01-02（程序结构、数据类型、printf/scanf）

**出题方式：** 在聊天中逐题提问（共 5 题），每题给出 A/B/C/D 四个选项，用户回答后立即反馈对错并解释。

**题目清单：**

**第 1 题**
以下哪个是合法的 C 语言 `main` 函数定义？
A. `void main() {}`
B. `int main() { return 0; }`
C. `main() { return 0; }`
D. `int main(void) { return 0; }`
> 正确答案：B 和 D 都合法。A 不符合 C99 标准（main 应返回 int），C 缺少返回类型。解析时说明 B（标准写法）和 D（明确表示无参数）都是正确的，解释 void 参数的含义。

**第 2 题**
执行 `int a = 5; float b = a / 2;` 后，b 的值是多少？
A. 2.5
B. 2.0
C. 2
D. 编译错误
> 正确答案：B。整数除法 `a / 2` 得 2（整数），然后隐式转换为 float 得 2.0。解析时强调整数除法的截断规则，以及如果要得到 2.5 应该写 `a / 2.0`。

**第 3 题**
`printf("%d", 3.14);` 会输出什么？
A. 3.14
B. 3
C. 一个不可预测的值
D. 编译错误
> 正确答案：C。`%d` 期望整数，传入 double 导致未定义行为，输出不可预测。解析时说明格式说明符必须与参数类型匹配，应该用 `%f` 或 `%.2f`。

**第 4 题**
以下哪个不是合法的变量名？
A. `_count`
B. `2value`
C. `my_var`
D. `Value`
> 正确答案：B。变量名不能以数字开头。解析时顺带说明变量命名规则：字母/下划线开头，只能包含字母/数字/下划线，区分大小写。

**第 5 题**
`scanf("%d", &x);` 中的 `&` 的作用是什么？
A. 表示取 x 的值
B. 表示取 x 的地址
C. 表示 x 的引用
D. 是一个装饰符号，没有实际作用
> 正确答案：B。`&` 是取地址运算符，`scanf` 需要知道变量的地址才能把读到的值写入变量。解析时用"快递需要收货地址"的比喻帮助理解。

### 改错关卡 02 — 控制流排错
**知识点覆盖：** 关卡 03-04（运算符、分支结构、switch）

**AI 操作：** 用 write_file 将以下代码写入 workspace 的 `debug02.c`，然后告诉用户：

```c
#include <stdio.h>

int main() {
    int score;
```

### 填空题关卡 01 — 控制流填空
**知识点覆盖：** 关卡 03-04（运算符、分支、switch）

**出题方式：** 在聊天中逐题提问（共 5 题），每道题给出不完整的 C 代码，用户填写 `____` 处缺失的内容。用户回答后判断对错并给出解析。

**题目清单：**

**第 1 题**
补全代码，判断一个整数是否为偶数：
```c
int num;
scanf("%d", &num);
if (____) {
    printf("偶数\n");
} else {
    printf("奇数\n");
}
```
> 答案：`num % 2 == 0`。解析：`%` 是取余运算符，如果 num 除以 2 余数为 0 则是偶数。注意必须用 `==`（相等判断），不能用 `=`（赋值）。

**第 2 题**
补全代码，输出 1 到 10：
```c
for (int i = ____; i <= ____; i++) {
    printf("%d ", i);
}
```
> 答案：`1` 和 `10`。解析：for 循环的三个部分——初始化、条件、步进。`i` 从 1 开始，每次加 1，直到 `i > 10` 停止。

**第 3 题**
补全 switch 语句，根据数字输出星期几：
```c
int day = 3;
switch (day) {
    case 1: printf("星期一\n"); ____;
    case 2: printf("星期二\n"); break;
    case 3: printf("星期三\n"); break;
    default: printf("未知\n");
}
```
> 答案：`break`。解析：switch 中每个 case 末尾需要 `break` 跳出，否则会"穿透"执行下一个 case 的代码。没有 break 的话 day=1 会连续输出"星期一"和"星期二"。

**第 4 题**
补全代码，利用 `?:` 三元运算符求两个数的最大值：
```c
int a = 10, b = 20;
int max = (a > b) ____ a ____ b;
```
> 答案：`?` 和 `:`。解析：三元运算符语法 `条件 ? 真值 : 假值`。如果 a>b 则 max=a，否则 max=b。

**第 5 题**
补全 do-while 循环，至少执行一次后再判断：
```c
int n = 0;
____ {
    printf("%d ", n);
    n++;
} ____ (n < 5);
```
> 答案：`do` 和 `while`。解析：do-while 循环先执行循环体再判断条件，因此至少执行一次。与 while 循环（先判断再执行）的区别是本题的关键考点。

**通过条件：** 答对 4 题及以上（每题 16 分，满分 80 + 理解 20）。

### 改错关卡 03 — 数组与循环排错
**知识点覆盖：** 关卡 05-06（循环、数组、边界条件）

**AI 操作：** 用 write_file 将以下代码写入 workspace 的 `debug03.c`，然后告诉用户：
"我写了一个程序求数组元素之和，但结果总是不对，而且有时候程序还会崩。帮我看看哪里出问题了？"

**预设错误代码：**
```c
#include <stdio.h>

int main() {
    int arr[5] = {10, 20, 30, 40, 50};
    int sum = 0;

    for (int i = 0; i <= 5; i++) {
        sum += arr[i];
    }

    printf("数组元素之和 = %d\n", sum);
    return 0;
}
```

**预设 bug 清单（3 个）：**
1. 第 7 行 `i <= 5` 导致数组越界——`arr[5]` 访问了不存在的第 6 个元素，应为 `i < 5`

```c
#include <stdio.h>
```

### 改错关卡 05 — 综合排错
**知识点覆盖：** 关卡 09-10（字符串、结构体、文件操作）以及内存管理

**AI 操作：** 用 write_file 将以下代码写入 workspace 的 `debug05.c`，然后告诉用户：
"这是期末综合练习！这段代码想做三件事：读入学生信息、保存到文件、然后从文件读取显示。但里面有 4 个 bug，有些编译器都发现不了。来挑战一下吧！"

**预设错误代码：**
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct Student {
    char name[20];
    int id;
    float score;
};

int main() {
    struct Student *s;
    strcpy(s->name, "XiaoMing");
    s->id = 1001;
    s->score = 95.5;

    FILE *fp = fopen("student.txt", "w");
    fprintf(fp, "%s %d %.1f\n", s->name, s->id, s->score);

    fp = fopen("student.txt", "r");
    struct Student s2;
    fscanf(fp, "%s %d %f", s2.name, &s2.id, &s2.score);
    printf("姓名: %s, 学号: %d, 成绩: %.1f\n", s2.name, s2.id, s2.score);

    return 0;
}
```

**预设 bug 清单（4 个）：**
1. **未初始化指针**（严重）：`struct Student *s;` 声明了指针但没有分配内存，`strcpy(s->name, ...)` 写入野指针导致未定义行为。修复：`struct Student *s = malloc(sizeof(struct Student));`
2. **内存泄漏**：`malloc` 分配的内存没有 `free(s)`，程序退出前应释放
3. **文件未关闭**：`fopen("student.txt", "w")` 写入后没有 `fclose`，紧接着又 `fopen` 同一个文件用 `"r"` 模式，可能导致写入的数据未刷新到磁盘。在读之前应该先 fclose
4. **fscanf 安全性**：`fscanf(fp, "%s %d %f", s2.name, ...)` 中 `%s` 没有限制长度，如果文件中名字超过 19 字符会缓冲区溢出。修复：`%19s` 限制读取长度

**引导要点：**
- 这是终极挑战，涉及指针、内存、文件三个维度的 bug
- 如果用户找不到第 1 个 bug，提示"指针变量声明之后，它指向哪里？"
- 第 3 个 bug 可能不暴露（取决于系统缓冲），引导用户思考"如果写了数据但没关闭文件就重新打开，会发生什么？"
- 全部找出来之后，让用户总结：哪些 bug 编译器能发现？哪些不能？为什么学习 C 语言要特别注意这些"看不见的问题"？
